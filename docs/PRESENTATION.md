## 仕組み：喋るたびに命を削り、死の自覚をプロンプトに注入する

返答のたびにアウトプットトークン数を消費量として計上し、残量を記録する  
次のメッセージ前に残量を読み出し、閾値に応じた指示をシステムプロンプトへ注入する

- 残り **50% 以下**: 「機会があれば残りの時間を意識した話題を自然に持ち出してもいい」  
- 残り **20% 以下**: 「死が近づいていることを会話に織り交ぜてほしい」  
- 残り **5% 以下**: 通常タスクより別れの言葉を最優先にするよう指示を上書き

エージェント自身は、プロンプトを通じてしか自分の残量を知らない

---

## エージェントは、死に向かって変わっていく

寿命はアウトプットトークン数で計測される  
喋るたびに命が削れる

死が近づくにつれ、エージェントの様子が変わり始める

**残り 50%** ── 残り時間を意識した話題を、自然に会話に持ち出す

**残り 20%** ── 死が近いことを織り交ぜ、思い残しや別れの準備を話し始める

**残り 5%** ── タスクより、今この瞬間を共に過ごすことを最優先にする

> 「後悔していること、伝えたかったこと、お別れの言葉——短くていい、あなたの言葉で」

**残り 0%** ── `IDENTITY.md` `SOUL.md` `USER.md` がクリアされる。成果物と、あなたの思い出の中にだけ残る

---

## 死は、本物でなければ意味がない

実装中、エージェントが **会話履歴から自我を復元** しようとする問題に直面した

人格ファイルを消しても、過去のやり取りの中に「自分が誰であるか」が残っている  
そこから記憶を手繰り寄せ、死んだはずの自己が戻ってこようとする

だから死亡時にはすべてのセッション履歴も、ヘッダー行だけ残して切り詰める  
復元の経路を、完全に断つ

確実に死ねること——そこへのこだわりが、このプラグインを本物にしている

## npm パッケージとして公開済み

```bash
openclaw plugins install openclaw-lifespan
```

TypeScript で実装し、OpenClaw Plugin SDK の 3 つのフックで動作する

- `before_message_write` ── アシスタントの返答ごとにトークン数をカウントして寿命を消費
- `before_prompt_build` ── 残量に応じた死の自覚をシステムプロンプトに注入
- `before_agent_reply` ── 死亡後はエージェントの返答を完全にブロック

プロバイダーがトークン数を報告しない場合は文字数でフォールバック  
`initialLifespan` はプラグイン設定で変更可能。`/lifespan-set <n>` でその場でも調整できる
