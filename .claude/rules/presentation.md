# ピッチスライド編集ルール

## トーン

冒頭は冗談っぽく入り、後半は本気のトーンで締める。

## スライド構成の順序

概念 → 仕組み（概念レベル） → 体験・行動変容 → 技術詳細 → メッセージ

## 記述の粒度

- ファイルパス・データ構造・JSON の例など実装の細部は書かない
- テスト・検証用に設定した値（トークン数など）は書かない
- 仕組みの説明は「何をしているか」の概念にとどめる

## スライドごとの量

1スライドに詰め込みすぎない。要点を絞って短く。

## 審査基準（編集時に常に意識すること）

| 基準 | 問い |
|---|---|
| テーマ適合性（AIエージェントの可能性を拡張せよ） | 寿命という制約が、エージェントの可能性をどう広げるかが伝わっているか |
| AIエージェントならではの体験 | これはAIエージェントだからこそ成立する体験として描けているか |
| 課題設定 | 解こうとしている課題（死なないから雑に扱われる）が明確に伝わっているか |
| 新規性 | アイデアの面白さ・意外性が出ているか |
| 完成度 | 実装済みで動くものとして説得力があるか |
